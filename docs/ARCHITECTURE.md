# BERHOT EVOLVE architecture (MVP 0.1)

## What is real

1. Long-lived controller process runs a bounded cycle, then sleeps.
2. Source discovery is automatic, using seeds for traversal and following eligible Wikidata item relationships.
3. Exactly one source connector is operational: fixed-host, per-entity Wikidata structured data (CC0), English and Arabic labels/descriptions, with local raw provenance.
4. Cleaning: Unicode NFC, whitespace and control-character normalization, max-length caps. Deduplication: canonical text SHA256 and source ID.
5. SQLite stores frontier, train/held-out documents, model versions, run history and verifiable experiment records.
6. A **randomly initialized** tiny causal Transformer performs next-byte learning in PyTorch.
7. Trained candidates are evaluated on persistently held-out documents, and compared to the current promoted model using the same currently available evaluation data.
8. Computer-generated arithmetic lessons are produced after source discovery. An independent integer verifier checks model arithmetic guesses and records successes/failures.
9. Strict intake gates and dormant connector interfaces anticipate approved media and social/API sources.

## Not implemented (do not mistake for existing capabilities)

- No autonomously learned research-goal planner. Discovery starts from engineered seed IDs and relationship navigation.
- No general web crawler, social feed reader, or image/video/3D model trainer.
- No model-generated mathematical curriculum; current exercises are generated by programmatic rules.
- No model weight changes merely from saving an experience; training occurs in candidate runs.
- No guarantee that tiny model can talk, reason, or perform mathematics after brief training.
- No guaranteed semantic dedup, legal determination of a webpage license, general fact verification, or prevention of all model-collapse/forgetting.
- No secure container sandbox for arbitrary AI-generated code (this MVP does not run such code).
- No GPU rental/provisioning API. GPU worker is optional and local to the machine running training.

## Research hypotheses

- H1: Automatically discovered source content can bootstrap basic language modeling without manually downloaded raw datasets.
- H2: A learned curiosity policy can outperform fixed or random discovery choices per unit cost.
- H3: Verified experiences can improve performance with fewer gradient updates using a skill memory.
- H4: Modular updates can outperform continual full-model fine-tuning on unseen tasks while limiting forgetting.

Current MVP tests H1's acquisition/training plumbing. It does **not** establish H2–H4.

## Safety and publication constraints

All online intake uses fixed Wikimedia API host, agent identification, bounded request counts, serial requests, delay, and bounded response size. Do not circumvent HTTP 429 or access restrictions. Downloaded content is untrusted data and cannot issue runtime commands. External connector media must have evidence of rights, provenance, lawful processing, and appropriate consent. Public social posts are not automatically legal training data. Avoid storing unnecessary personal data. No autonomous model release without independent evaluation and policy approval in high-impact settings.

## Scale-out after experiments

Replace the SQLite+local architecture when required with a durable task system, PostgreSQL, object storage such as Cloudflare R2, trained-model registry, explicit training set freeze/versioning, immutable and blinded evaluation sets, proper RBAC, audit logs, managed compute, budget enforcement and human change approval.
