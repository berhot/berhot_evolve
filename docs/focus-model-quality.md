# Why the earlier model produced incoherent continuations

The reported examples came from the earlier accepted checkpoint `9044d8757703…`, a local
2,626,304-parameter byte GRU with 4,920 accepted optimizer steps. Its saved
validation loss improved from 0.906659 to 0.900622 on that training attempt.
This metric measures next-byte prediction, not fluent Arabic, historical
accuracy, instruction following, or question answering.

The training objective uses 48-byte windows. Arabic letters commonly occupy
multiple UTF-8 bytes, so these are very short spans of language. The model
has no instruction-tuning or historical-answer evaluation in this pipeline.

Inspection of that checkpoint's immutable `train.txt` found 694 occurrences
of `جدول المحتويات`. Existing cleaning normalized Unicode/whitespace and
deduplicated entire documents, but did not consistently isolate the article
body from page interface content. Increasing parameters did not remove that
text or change the learning objective.

The two reported prompts were reproduced. A separate diagnostic recomputed
every prediction from the most recent 48 bytes, matching the training window;
the first 128 generated bytes were identical to the current sampler for both
prompts. That experiment did not fix the output, so the problem cannot be
attributed to the chat interface or solved by claiming a decoding repair.
The checkpoint path/hash and actual weights were verified. No retrieved
passage, remote model, or corrected historical answer was substituted.

The model remains a from-scratch text-prediction experiment. Usable historical
chat requires a different capability target: article-body data cleaning,
longer coherent text training, appropriate instruction/answer training, and
independent fluency and factuality evaluation. Alternatively, a separate local
pretrained Arabic-capable instruction model could provide conversation while
preserving this experiment. Neither option implies that collected articles
automatically become reliable knowledge in model weights.

The chat API now exposes the training objective, context length, and lack of
historical-QA evaluation explicitly. Future training records also include
the context and validation metric. Existing datasets and checkpoints are
preserved.

The active project now uses [PyTorch with your own model](pytorch-from-scratch.md)
with article-body cleaning and 256-byte training windows. The original model
was preserved and its weights migrated without an external model download.
This is measured training progress; historical-answer accuracy is still
unverified and generated text still needs improvement.
